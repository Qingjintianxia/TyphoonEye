台风预警系统优化改进方案

对现有 Vue 3 + Express 台风预警系统的一次全面体检。结论是：骨架是对的，但停在"能跑的原型"阶段——数据全静态、无实时能力、无设计系统、无安全基线。本方案按四个阶段给出可落地的改造路径。

技术栈 Vue 3 + Vite + Pinia + ECharts + Leaflet / Express 4 规模 前端 20 文件 · 后端 8 文件 评审日期 2026-09-22

01总体判断

先说结论，再说细节

这套代码的优点很明确：目录分层清晰（views / components / stores / routes 各司其职），Pinia store 已按领域拆分，暗色玻璃拟态的视觉方向统一，路由守卫和 JWT 鉴权的链路是完整的。它是一份合格的课程作业或原型，但距离"预警系统"这个定位还差得远。

致命

名不副实的"实时"

所有数据来自 server/data/mock-data.js 的内存常量，服务重启即丢，"实时监控""最新预警"均无实际含义。

致命

安全基线缺失

JWT 密钥硬编码、密码文件同步读写无锁、CORS 全开、无限流、token 存 localStorage 无刷新机制。

严重

无设计系统

预警色板、等级映射、图标 SVG 在每个组件各抄一遍；颜色硬编码不用变量；无加载/空/错误三态统一规范。

2.2 数据真实性：页面上的假数据

这一条最影响可信度

以下数字与后端数据完全无关，是写死在前端/后端的常量。演示时任何一次数据改动都会让图表自相矛盾。

  • Dashboard.vue:8,15,22,29 — 四张 StatCard 的 :trend 分别是写死的 12 / 8 / 25 / -5，"较昨日"是假的。
  • server/routes/statistics.js:14-36 — monthlyData 与 levelDistribution 硬编码，不随台风数据变化。
  • HistoryView.vue:76-83 — 年度强度分布饼图数据硬编码；:92,:104 — 2018–2025 趋势线硬编码。
  • HistoryView.vue:11 — 写死"2025年度"，而 mock 数据里已有 2026 年的台风。

建议：统计口径全部下沉到服务端聚合（或至少由 mock 数据实时计算），前端只负责渲染。同时引入"数据更新时间"字段并在 UI 显式展示，避免用户误判新鲜度。

2.5 风格与工程化

  • 重复代码严重：warn-blue/yellow/orange/red 四个色样式在 TyphoonTable、AlertPanel、AlertCenter、TyphoonMonitor 各抄一遍；levelMap（等级→badge）复制 3 份；warningLabel() 复制 4 份；authHeaders() 在三个 store 各写一遍。改一个颜色要动 4 个文件。
  • 无设计 token：颜色除 global.css 的变量外，大量 #3b82f6、#0f1923、#8899aa 直接硬编码在组件和 ECharts option 里；字号、间距、圆角没有 scale，全靠手感。
  • 交互缺失：表格无排序/分页；详情页风圈用固定像素圆环（r7=160px、r10=120px、r12=80px），半径比例与实际数值无关，视觉误导严重；无骨架屏；表格行 @click 不能键盘访问；无 focus / aria 属性。
  • 响应式缺失：侧边栏固定 240px，768px 以下不折叠；body{overflow:hidden} + 固定 100vh 在移动端体验很差；地图 min-height:500px 与 flex 布局冲突。
  • 工程化为零：无 TypeScript、无 ESLint / Prettier、无测试、无 CI、无 .env.example、无 .gitignore、无 README、无日志中间件、无健康检查接口。前后端需手动分别启动两个终端。
  • 详情页最大缺陷：台风详情页只有表格和文字时间线，没有地图。对一个台风系统来说这是最该有的东西。

06UI 风格改造要点

现有暗色方向是对的，问题是"没有规范"

建立语义色板

现在 blue/yellow/orange/red 既是台风等级色又是预警等级色，语义混用。应拆成两套：

  • 预警信号色（蓝黄橙红）——严格对应国内气象预警四色标准，这是用户唯一需要条件反射识别的色系
  • 强度色（热带低压→超强台风）——用低饱和的连续色阶，与预警色区分开
  • 组件内禁止写十六进制，一律走 CSS 变量

补齐三态规范

当前只有一行"加载中..."。需要统一的：

  • Skeleton — 卡片与表格首屏骨架屏
  • EmptyState — 带图标与引导动作的空态
  • ErrorState — 带重试按钮的错误态
  • 全局 Toast 与确认弹窗

信息与密度分层

当前所有信息同一权重：仪表盘四张卡、两个图、一个表、一个列表平均用力。建议：

  • 顶部放"当前最紧急的事"——活跃台风中最强的一个 + 最高预警
  • 时间统一相对化（"12 分钟前更新"）并标注数据新鲜度
  • 数字用等宽字体对齐，避免跳动

去掉失真的装饰

  • 风圈圆环改为按真实半径比例绘制，并叠加到地图上
  • stat-glow 光晕、backdrop-filter 在列表项上大规模使用会拖慢滚动，只在浮层上保留
  • 动画时长统一，尊重 prefers-reduced-motion
