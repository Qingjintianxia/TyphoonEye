# P0-3 清除硬编码假数据 · 统计实时聚合 规范

> 目标：消除前端/后端中写死的"假数据"，所有统计指标改为从台风数据**实时计算**。
> 依据：`server/data/mock-data.js` 中 8 个台风（2025 年 5 个、2026 年 3 个）的真实分布。

## 1. 改造前的问题

| 位置 | 硬编码内容 | 与真实数据的偏差 |
|------|-----------|------------------|
| `server/routes/statistics.js:14-36` | 月度 12 个月频次、强度分布 6 类数值 | 全部写死，不随数据变化；强度分布与真实严重不符（真实：超强2/强台2/台风2/强热带风暴1/热带风暴1） |
| `src/views/Dashboard.vue` | 四张卡片 `:trend` 写死 12/8/25/-5（"较昨日"为编造） | 伪造趋势 |
| `src/views/HistoryView.vue:67-132` | 饼图强度分布、历年趋势线（2018–2025）全写死 | 数据虚构，年份与真实（仅 2025/2026）不符 |
| `src/views/HistoryView.vue` | 摘要卡片标注"2025年度" | 数据含 2026，年份误导 |

## 2. 改造方案

### 2.1 后端（`server/routes/statistics.js` 重写）
所有指标由 `typhoons` 实时计算：
- `monthlyData`：按 `startTime` 月份聚合，12 个月（缺失为 0）。
- `levelDistribution`：按规范顺序（热带低压→超强台风）统计，缺失等级记 0。
- `yearTrend`：按年聚合 `{ year, total, super }`（`super` = 强台风+超强台风数），按年升序。
- `year`：数据中最新的年份，供前端标题参考。
- 保留 `activeCount / alertCount / redAlertCount / affectedCityCount / totalHistorical` 的实时计算。

### 2.2 前端
- **Dashboard**：移除写死的 `:trend`（StatCard 不再传趋势）；柱状图标题改为"月度台风频次"，不再挂误导年份；图表数据消费 `/api/statistics` 的 `monthlyData` / `levelDistribution`。
- **HistoryView**：新增 `loadStats()` 调用 `/api/statistics`，饼图与趋势线改为由 `levelDistribution` / `yearTrend` 渲染；摘要卡片"2025年度"改为"历年累计"。
- 两家视图均带 loading / error（ErrorState 重试）兜底。

## 3. 验收口径（对照真实数据）
- [ ] `GET /api/statistics` 返回：`levelDistribution`=[2,1,1,2,2,0]（按规范顺序：热带低压0/热带风暴1/强热带风暴1/台风2/强台风2/超强台风2）；`monthlyData` 仅 5–9 月有值（3/1/2/1/1）。
- [ ] `yearTrend` 含 2025(总5) 与 2026(总3) 两项，super 分别为 2 与 2。
- [ ] Dashboard 卡片无"较昨日"趋势；柱状图标题无年份。
- [ ] HistoryView 饼图与趋势线与上述聚合一致，无写死数组。
- [ ] 构建通过，无控制台报错。
