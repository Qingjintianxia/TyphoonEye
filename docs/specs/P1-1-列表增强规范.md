# P1-1 列表增强（搜索 / 筛选 / 排序）规范

## 1. 背景与问题

当前台风列表是纯静态渲染，交互能力缺失：

- `TyphoonTable.vue` 只是 `v-for` 渲染传入数组，无搜索、无筛选、无排序。
- `TyphoonMonitor.vue` 侧栏只能用 `activeTyphoonsByLevel`（强度降序）这一种固定顺序，无法按风速、气压或更新时间排序。
- 数据量小（8 条）时问题不明显，一旦台风数量或历史数据增长，列表立即不可用。

此外发现一处 P0 遗留：**预警色样式仍有重复定义**。`global.css` 已将 `.warn-tag` + `.warn-{level}` 收敛为单一数据源（其注释明确写着"共 4 份重复，统一收敛到此处"），但 `AlertCenter.vue:124-127` 与 `TyphoonMonitor.vue:120-123` 各自又保留了一份私有 `.warn-*`。本轮一并清除。

## 2. 目标与非目标

**目标**

- 关键词搜索：命中台风中文名、英文名、编号。
- 多维筛选：强度等级（多选）、预警色（多选）、状态（活跃/历史/全部）。
- 多字段排序：强度等级、最大风速、中心气压、更新时间，支持升降序切换。
- 结果计数与空结果态，一键清除全部筛选。
- 表头可点击排序，键盘可达。

**非目标**

- 不做分页（当前数据量不需要，且滚动列表体验更好；数据量增长后再引入）。
- 不做 URL 同步筛选条件（本期不引入路由 query 持久化）。
- 不做服务端筛选（mock 数据全量下发，前端过滤足够；P2 实时化后再评估）。

## 3. 设计

### 3.1 数据流：筛选逻辑必须单一来源

前序评审已吃过"同一份逻辑散落 3–4 处"的亏。因此：

- 新建 `src/composables/useTyphoonFilter.js`，导出筛选/排序的**纯函数** `filterTyphoons(list, query)` 与响应式封装 `useTyphoonFilter(sourceRef)`。
- 视图**只负责渲染控件与绑定条件**，不得自行写 `filter` / `sort`。
- 排序字段与方向的定义收敛到 `src/constants/typhoon.js` 的 `SORT_OPTIONS`，不散落在组件里。

### 3.2 筛选条件模型

```js
{
  keyword: '',          // 匹配 name / nameEn / id，忽略大小写
  levels: [],           // 强度等级多选，取 TYPHOON_LEVELS[].key
  warnings: [],         // 预警色多选，取 WARNING_LEVELS[].key
  status: 'all',        // 'all' | 'active' | 'historical'
  sortBy: 'level',      // 取 SORT_OPTIONS[].key
  sortOrder: 'desc'     // 'asc' | 'desc'
}
```

判定"是否处于筛选态"：keyword 非空 或 levels/warnings 非空 或 status !== 'all'。（排序不算筛选，不触发"清除筛选"。）

### 3.3 排序语义（关键，避免歧义）

`SORT_OPTIONS` 每个字段自带**语义化默认方向**，UI 下拉直接展示方向含义，不出现"按气压排序"这种有歧义的表述：

| key | 标签 | 默认方向 | 含义 |
|---|---|---|---|
| `level` | 强度等级（强→弱） | `desc` | 用常量层已有的 `compareLevel` 比较，保证与 `TYPHOON_LEVELS` 顺序一致 |
| `windSpeed` | 最大风速（高→低） | `desc` | 数值越大越强 |
| `pressure` | 中心气压（低→高） | `asc` | **气压越低越强**，故默认升序把最强排前面 |
| `updateTime` | 更新时间（新→旧） | `desc` | 用 `parseTime` 解析后比较时间戳 |

`sortOrder` 仅控制**数值方向反转**，不针对字段做隐式特殊反转——避免"为什么气压排序是反的"这类困惑。方向语义全部由 UI 标签显式表达。

### 3.4 空值防御

延续 `utils/format.js` 的约定（空值绝不抛异常）：

- 参与排序的数值字段为 `null/undefined/NaN` 时，统一视作**最小值**排到末尾（升序时在最前则会误导，故统一按"缺失排最后"处理，与方向无关）。
- `safeList()` 处理 `affectedCities` 等可能为 undefined 的数组。
- 时间解析失败（`parseTime` 返回 null）按缺失处理。

实现方式：比较函数先取"缺失标记"，缺失项恒排在后面，再有 `(a,b) => (va-vb) * dir`。

### 3.5 组件划分

| 文件 | 职责 | 变更 |
|---|---|---|
| `src/constants/typhoon.js` | 领域常量 | **新增** `SORT_OPTIONS` |
| `src/composables/useTyphoonFilter.js` | 筛选/排序纯逻辑 | **新建** |
| `src/components/TyphoonFilterBar.vue` | 搜索框 + 筛选 chip + 排序下拉 + 清除 | **新建** |
| `src/components/TyphoonTable.vue` | 列表展示 | 表头可排序（受控 props + emit），空态增强 |
| `src/views/TyphoonMonitor.vue` | 监控页 | 集成 FilterBar，侧栏改用过滤结果；**删除私有 `.warn-*`** |
| `src/views/AlertCenter.vue` | 预警中心 | **删除私有 `.warn-*`**，改用全局 `.warn-tag` |

`TyphoonTable` 保持"受控展示"定位：接收已过滤数组，同时通过 `sortBy` / `sortOrder` props 与 `@sort` 事件支持表头点击排序，自身不持有筛选状态。

## 4. 交互与可达性

- **筛选 chip**：强度等级与预警色用可点击的 chip 按钮（点击切换选中），比多选下拉操作更快、状态更直观。使用原生 `<button>`，天然支持 Enter/Space 与焦点。
- **搜索防抖**：输入防抖 200ms，避免每输入一个字符就重算整表。
- **结果计数**：展示"共 N 条"，处于筛选态时展示"筛选出 M / N 条"。
- **空结果态**：显示"没有符合条件的台风" + "清除筛选"按钮，而非空白。
- **清除筛选**：一键重置 keyword / levels / warnings / status，不影响当前排序。
- **配色**：预警 chip 的选中态颜色一律取 `warningColor()`，强度 chip 取 `levelColor()`，**禁止再写字面色值**。

## 5. 样式与去重

- 复用现有 CSS 变量（`--bg-card`、`--border`、`--blue`、`--text-muted` 等），不新增硬编码色。
- 删除 `AlertCenter.vue` 与 `TyphoonMonitor.vue` 中的私有 `.warn-*` 定义，元素改用全局 `.warn-tag warn-{level}` 组合。
- `TyphoonFilterBar` 样式放组件 scoped，通用 chip / 表单控件若后续复用再上提到全局（遵循"重复 3 次才抽象"）。
