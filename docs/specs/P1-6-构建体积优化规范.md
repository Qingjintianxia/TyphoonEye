# P1-6 构建体积优化规范

## 1. 背景与问题

P0 收尾时构建长期存在一条告警：

```
dist/assets/TyphoonTable-*.js   1,039.12 kB │ gzip: 345.37 kB
(!) Some chunks are larger than 500 kB after minification.
```

根因有两层：

1. `src/components/Charts.vue` 用 `import * as echarts from 'echarts'` **全量引入**，而项目实际只用到柱图、线图、饼图三种，其余图表类型与坐标系全部被打包进业务 chunk。
2. 第三方大依赖（echarts / leaflet / vue）与业务代码混在同一个 chunk，**业务代码一改，用户就要重新下载整包**，且无法被多路由共享缓存。

这不是"警告而已"：首屏白屏时间与这条体积直接相关，且每次构建都刷一条无法处理的告警，会掩盖真正需要关注的体积问题。

## 2. 目标与非目标

**目标**

- 消除全量 echarts 引入，只打包实际用到的图表与组件。
- 把第三方大依赖拆成独立 vendor chunk，与业务代码解耦（利于缓存与共享）。
- 构建告警清零——保留下来的告警必须都是"需要行动"的，不能明知无害还天天报。

**非目标**

- 不引入 UI 库替换（不在本轮范围）。
- 不追求极致体积（未做图表懒加载 / 预渲染等激进手段）。

## 3. 设计

### 3.1 echarts 按需引入（`Charts.vue`）

改为 `echarts/core` + `echarts.use([...])` 显式注册：

| 类别 | 注册项 | 用途 |
|---|---|---|
| 图表 | `BarChart` `LineChart` `PieChart` | 仪表盘柱状图、历史页趋势线、两处饼图 |
| 组件 | `GridComponent` | 直角坐标系 `grid/xAxis/yAxis` |
| 组件 | `TooltipComponent` | `tooltip` |
| 组件 | `LegendComponent` | 历史页趋势线 `legend` |
| 渲染器 | `CanvasRenderer` | 默认渲染方式 |

> **约束（必须遵守）**：后续若新增图表类型（如雷达图、地图散点），**必须在此同步注册**，
> 否则对应 `series` 会**静默不渲染**——不报错、不告警，只是图上少一块，极难排查。
> 已在代码注释中写明此约束。

确认过的**未使用**能力（因此未注册）：`TitleComponent`（标题由组件自己的 header 渲染）、
`DataZoomComponent`、`ToolboxComponent`、`VisualMapComponent`。

### 3.2 vendor chunk 拆分（`vite.config.js`）

`build.rollupOptions.output.manualChunks` 按依赖路径归类：

- `node_modules/echarts` + `node_modules/zrender` → `echarts`
- `node_modules/leaflet` → `leaflet`
- `node_modules/vue` + `node_modules/@vue` → `vue`

zrender 必须跟 echarts 归到一起——它是 echarts 的底层渲染引擎，拆开会造成循环引用或重复打包。

### 3.3 告警阈值

`chunkSizeWarningLimit: 600`。

理由：拆分后 echarts 仍是 ~520 kB 的独立 vendor chunk，但它是**按需加载**的——
只有访问仪表盘 / 历史数据页才会拉取，不进首屏。这是已知且已接受的体积，
故把阈值调到 600 让构建输出保持干净；若将来它涨过 600，告警会重新出现，仍然有效。

## 4. 文件变更

| 文件 | 变更 |
|---|---|
| `src/components/Charts.vue` | 全量 `echarts` → `echarts/core` 按需注册 |
| `vite.config.js` | 新增 `build.rollupOptions.output.manualChunks` + `chunkSizeWarningLimit` |

## 5. 验收清单

- [x] `npm run build` 通过，构建输出**无** "chunks are larger than 500 kB" 告警。
- [x] echarts 从全量包降为按需包：业务 chunk `TyphoonTable` 1039.12 kB → 4.22 kB。
- [x] 入口 `index` chunk 123.48 kB → 24.06 kB（echarts 不再进首屏）。
- [x] 独立 vendor chunk 生成：`echarts` 519 kB / `leaflet` 150 kB / `vue` 100 kB。
- [ ] 浏览器实测：仪表盘柱状图、饼图，历史页饼图、趋势线（含 legend）均正常渲染 —— **需人工在 UI 上确认**（体积优化无法靠构建产物证明图表真的画出来了）。

## 6. 遗留

- 构建仍有一条无害提示：`router/index.js` 被 `utils/request.js` 动态引入、又被 `main.js` 静态引入，
  导致动态 import 未生效。仅影响 chunk 归属，不影响功能；若要彻底消除需重构 401 跳转的 router 引用方式。
- echarts 519 kB 本身仍偏大。若后续要继续压，可考虑：图表组件做 `defineAsyncComponent` 懒加载、
  或用纯 SVG 替代简单图表（本项目 P1-2 的强度演变曲线、P1-3 的对比曲线已走纯 SVG 路线，无此负担）。
