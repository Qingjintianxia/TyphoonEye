# P0-2 后端安全基线加固 规范

> 目标：消除"源码泄露即可伪造任意 token / 同步阻塞 / 并发丢数据 / 任意域可调用 / 无防护头"五类致命隐患。
> 范围：`server/` 全部后端代码。本阶段**不改业务逻辑与数据结构**，只做安全横切加固。

## 1. 问题清单（改造前）

| 位置 | 问题 | 风险 |
|------|------|------|
| `middleware/auth.js:3` | JWT 密钥硬编码 `'typhoon-eye-secret-key-2026'`，源码泄露即被伪造 | 严重 |
| `routes/auth.js:43,72` | `bcrypt.hashSync/compareSync` 同步调用，阻塞事件循环 | 中 |
| `routes/auth.js:15-17` | `fs.writeFileSync` 无锁，并发注册互相覆盖 | 高（丢数据） |
| `index.js:8` | `cors()` 全开，任意站点可调用 | 中 |
| `index.js` | 无 helmet、无登录限流、无统一错误处理 | 中 |

## 2. 改造方案

### 2.1 配置集中化（`server/config.js` 新建）
- 所有环境相关量从 `process.env` 读取，源码中**不出现任何密钥字面量**。
- JWT 密钥策略：
  - 生产环境（`NODE_ENV=production`）下若 `JWT_SECRET` 缺失 → **启动即失败**（fail-fast），绝不回退到默认密钥。
  - 开发环境缺失 → 启动时生成一次性随机密钥并**打印显著警告**（重启失效，足够本地联调）。
- 新增极简 `.env` 解析器（无 dotenv 依赖）：若存在 `.env` 则读取，缺省不报错。
- 提供 `.env.example` 作为配置清单。

### 2.2 CORS 白名单（`server/index.js`）
-  origins 来自 `config.corsOrigins`（默认 `http://localhost:5173`），不再 `cors()` 全开。
- 保留 `credentials: true` 时 origins 不设为 `*`（二者互斥）。

### 2.3 安全响应头（helmet）
- 引入 `helmet`，默认开启 HSTS/Content-Security-Policy/NoSniff 等。
- 关闭 CSP 对 `data:` 内联的阻断（本项目地图/图表用内联样式，保留默认即可，必要时 `helmet({ contentSecurityPolicy: false })` 兜底）。

### 2.4 登录限流（`server/middleware/rateLimit.js` 新建）
- 对 `POST /api/auth/login` 施加 `express-rate-limit`：每 IP 15 分钟 10 次，超限返回 429 与统一错误体。
- 注册接口同样限流（防批量撞库），阈值略宽。

### 2.5 用户写串行化（`server/routes/auth.js`）
- 引入"异步互斥锁"：用一个 promise 链 `writeQueue` 串行化 `writeUsers`，消除并发覆盖。
- bcrypt 改为异步 `bcrypt.hash` / `bcrypt.compare`，不再阻塞事件循环。

### 2.6 统一错误处理（`server/middleware/errorHandler.js` 新建）
- 兜底 `app.use(errorHandler)` 捕获同步/异步异常，返回 `{ code:500, message:'服务器内部错误' }`，生产不泄露堆栈。
- 404 兜底（无匹配路由）→ 统一 JSON 错误体，而非 Express 默认 HTML。

## 3. 验收口径
- [ ] 源码中搜索不到任何 JWT 密钥字面量。
- [ ] 生产环境无 `JWT_SECRET` 时进程直接退出并提示。
- [ ] 同一毫秒并发 5 次注册，最终 `users.json` 含全部 5 个用户（无覆盖丢失）。
- [ ] 非白名单 Origin 请求被 CORS 拒绝。
- [ ] 登录连续失败 10 次后第 11 次返回 429。
- [ ] 未知路径返回 JSON 错误体而非 HTML。
- [ ] `npm install` 新增 helmet / express-rate-limit 两项依赖，构建与启动正常。
