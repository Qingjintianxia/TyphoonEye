# P1-3 多台风路径叠加对比规范

## 1. 背景与问题

现有系统只能**逐个**看台风：详情页一次展示一个台风的路径与强度。但真实决策场景经常需要横向比较：

- 今年这个台风，和历史上的哪个台风路径/强度相似？
- 两个同时活跃的台风，谁的威胁更大？
- 同一区域历年台风的强度演化有何差异？

mock 数据已有 8 个台风（3 个活跃 + 5 个历史），每个都带完整 `path[]`，具备对比的数据基础，但目前这份数据只在单台风视图里被用到。

## 2. 目标与非目标

**目标**

- 新增"路径对比"页面（路由 `/compare`）。
- 勾选 **2–4 个**台风进行横向对比。
- 地图**叠加**多条路径，各自配色并配图例。
- 并列指标对比：强度等级、最大风速、中心气压、7 级风圈、影响城市数、状态。
- 多序列风速演变曲线对比。

**非目标**

- 不做路径相似度/匹配算法（需要更大数据集，属 P2）。
- 不做对比结果导出。
- 不做选择状态的持久化（本期仅内存态，刷新即重置）。

## 3. 设计

### 3.1 入口与路由

- 新增路由 `/compare` → `views/TyphoonCompare.vue`，`meta.title = '路径对比'`。
- `AppLayout` 侧栏新增导航项，与"监控/预警/历史"同级。
- 监控页提供"路径对比"入口按钮，形成自然动线。

### 3.2 选择约束

- **最少 2 个、最多 4 个**。上限 4 的理由：超过 4 条路径叠加后地图与曲线都会拥挤到不可读，这是可读性约束而非技术限制。
- 达到上限时继续勾选应被拒绝并给出提示（按钮置灰 + 文案说明），而不是静默忽略。
- 提供"清空选择"与单项移除。

### 3.3 配色

- 新增常量 `COMPARE_COLORS`（4 色），定义在 `src/constants/typhoon.js`。
- 这 4 色需与**预警四色**、**强度色阶**在语义上区分开——它们表达的是"这是第几个被对比的台风"，不是危险程度。
- 组件内禁止写字面色值，一律取常量。

### 3.4 地图（`TyphoonCompareMap.vue`，新建）

- 每个台风一条折线，取 `COMPARE_COLORS[i]`；末端点画"当前位置"标记。
- 使用 `map.fitBounds()` 自动把所有路径纳入视野，避免手工设定中心与层级。
- 复用 P0-4 的合规底图配置与无 key 海图降级，行为与详情页地图一致。
- 图例列出台风名与对应颜色。

### 3.5 指标对比（表格形态）

- 行 = 指标，列 = 台风，每个台风一列卡片/表格列。
- **突出最强项**：风速最大、气压最低、风圈最大的单元格做视觉强调（加粗 + 主色），让用户不必逐格比对数字。
- 空值一律显示 `—`（复用 `format.js` 的空值约定）。
- 状态用 `statusMeta()`，等级用 `levelBadgeClass()`，不重新定义样式。

### 3.6 曲线对比（`TyphoonCompareChart.vue`，新建）

- 多序列 SVG 折线，与 P1-2 保持一致：**不引入 echarts**（避免放大 `TyphoonTable` 已有的 1MB chunk 问题）。
- **X 轴按"路径点序号"对齐，而非绝对时间**。理由：不同台风生命史长度差异大（3–8 个点），按绝对时间对齐会让短生命史台风挤在左侧；按序号对齐更能反映强度演化的**形态**差异，这也是对比的核心诉求。此取舍需在图上注明。
- 每条序列用 `COMPARE_COLORS[i]`，图例可点选显示/隐藏某条（可选能力，本期实现图例即可）。
- 单条序列无有效风速数据时跳过该序列。

### 3.7 空值与边界

- 选中不足 2 个 → 展示引导态"请至少选择 2 个台风进行对比"，不渲染地图与曲线。
- 某台风无 `path` → 指标卡仍展示，曲线跳过该序列，不报错。
- 数据加载失败 → 复用 `ErrorState` 与重试。
