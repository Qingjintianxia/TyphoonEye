# P0-0 基础设施层规范

> 阶段：P0 止血与夯实 · 第 1 步
> 状态：已实施
> 日期：2026-09-22

## 1. 背景与问题

评审发现常量与工具逻辑在项目中被大量复制粘贴，形成"改一处要动四个文件"的维护陷阱：

| 重复内容 | 出现位置 | 份数 |
|---|---|---|
| `warn-blue/yellow/orange/red` 四个色样式 | `TyphoonTable.vue`、`AlertPanel.vue`、`AlertCenter.vue`、`TyphoonMonitor.vue` | 4 |
| `levelMap`（强度等级 → badge 类） | `TyphoonTable.vue`、`TyphoonMonitor.vue`、`TyphoonDetail.vue` | 3 |
| `warningLabel()` / `levelLabel()` | `TyphoonTable.vue`、`AlertPanel.vue`、`AlertCenter.vue`、`TyphoonMonitor.vue`、`TyphoonDetail.vue` | 5 |
| `authHeaders()`（拼接 Bearer token） | `stores/typhoon.js`、`stores/alert.js`、`stores/auth.js` | 3 |
| `t.latitude.toFixed(1)` 类坐标格式化 | `TyphoonMonitor.vue`、`TyphoonDetail.vue` | 2 |

同时，所有 `fetch` 调用均为裸调用：无超时、无错误提示、无 401 拦截，失败时页面静默显示 0。

## 2. 目标

建立**单一事实来源（Single Source of Truth）**：

1. 等级、颜色、文案等常量只在一处定义，其余全部引用。
2. 格式化逻辑只在一处实现，且对空值安全。
3. 网络请求只走一个封装，统一处理鉴权、超时、错误与 401。
4. 用户反馈（Toast）有统一入口。

本步不改动任何 UI 表现，仅做底层收敛，为后续 P0-1 ~ P0-5 提供支撑。

## 3. 设计

### 3.1 常量层 `src/constants/typhoon.js`

关键设计：**语义分离**。评审指出原实现把"预警信号色"与"台风强度色"混用同一套蓝黄橙红，造成语义冲突。本规范将二者拆开：

- `WARNING_LEVELS`：气象预警四色（蓝/黄/橙/红）。这是用户需要条件反射识别的标准色系，**不可挪作他用**。
- `TYPHOON_LEVELS`：强度等级（热带低压 → 超强台风）。使用低饱和连续色阶，与预警色在视觉上可区分。

两者均定义为**有序数组**（而非对象字面量），因为需要保序渲染图例与计算强度排名。派生对象 `LEVEL_META` / `WARNING_META` 由数组生成，供组件 O(1) 查表。

```js
export const WARNING_LEVELS = [
  { key: 'blue',   label: '蓝色预警', color: '#3b82f6', varName: '--blue'   },
  { key: 'yellow', label: '黄色预警', color: '#f59e0b', varName: '--yellow' },
  { key: 'orange', label: '橙色预警', color: '#f97316', varName: '--orange' },
  { key: 'red',    label: '红色预警', color: '#ef4444', varName: '--red'    }
]
```

### 3.2 工具层 `src/utils/format.js`

所有函数遵循**空值安全**原则：入参为 `null` / `undefined` / `NaN` 时返回占位符 `'—'`，绝不抛异常。这是修复 `TyphoonMonitor.vue:52` 白屏缺陷的基础。

| 函数 | 签名 | 说明 |
|---|---|---|
| `formatCoord` | `(lat, lng) => string` | `21.5°N, 126.8°E`；空值返回 `—` |
| `formatNumber` | `(v, { unit, digits, fallback }) => string` | 数值 + 单位 |
| `formatWind` | `(v) => string` | 风速，附带 `m/s` |
| `formatPressure` | `(v) => string` | 气压，附带 `hPa` |
| `formatDateTime` | `(v) => string` | `YYYY-MM-DD HH:mm` |
| `relativeTime` | `(v) => string` | `12 分钟前`；超过 7 天退回绝对时间 |
| `toISOTime` | `(v) => string \| null` | 统一时间格式，修复 `'2026-05-19 14:00'` 在严格 ISO 环境解析失败的问题 |

### 3.3 请求层 `src/utils/request.js`

```js
request.get(path, params)   // GET，params 自动序列化为 query
request.post(path, body)    // POST
request.put(path, body)
request.del(path)
request.raw(path, options)  // 逃生舱，不走统一解包
```

行为约定：

| 事项 | 约定 |
|---|---|
| baseURL | `/api`（与 vite proxy 对齐） |
| 超时 | 15 秒，使用 `AbortController` |
| 鉴权 | 自动读取 token 注入 `Authorization: Bearer <token>` |
| 解包 | 后端 `{ code, data, message }`；`code === 200` 返回 `data`，否则抛 `ApiError` |
| 401 | 清除本地 token、跳转 `/login`、弹出提示。**全局只处理一次**，避免并发请求重复跳转 |
| 网络错误 | 抛出带友好文案的错误，由调用方或 `handleError` 统一 toast |
| 取消 | 支持传入 `signal`，供组件卸载时中止 |

### 3.4 提示层 `src/utils/toast.js` + `src/components/ToastHost.vue`

响应式队列，`useToast()` 暴露 `success / error / info / warning`。`ToastHost` 在 `App.vue` 全局挂载一次。

### 3.5 错误处理约定

业务代码一律使用如下模式，禁止裸 `fetch`：

```js
try {
  data.value = await request.get('/typhoons')
} catch (e) {
  // request 层已对 401 与网络错误做全局处理，此处只做局部降级
} finally {
  loading.value = false
}
```

## 5. 验收标准

1. 全项目搜索 `Bearer ` 字面量，仅 `utils/request.js` 一处命中。
2. 全项目搜索 `#3b82f6` 等颜色字面量，组件内命中数下降（ECharts option 允许保留，后续 P1 处理）。
3. 断网情况下任意页面操作均有 Toast 提示，不出现静默失败。
4. token 失效时跳转登录，且不重复跳转。
5. `npm run build` 通过。

## 6. 风险与回退

- 本步为纯新增 + `App.vue` 挂载，不改动任何既有调用方，可独立回退（删除 `App.vue` 中两行即可）。
- 请求层尚未被 store 接入，接入动作放在 P0-1，便于分步验证。
