# P2-3 消息中心与未读通知规范

## 1. 背景与问题

预警能自动生成了（P2-1），工单能流转了（P2-2），但**当事人不会知道自己被点名了**：
工单指派给谁、状态什么时候变的、有没有新的处置意见，全靠用户自己去列表里翻。

这就是业务闭环的最后一公里——**事件要主动找到人**。

## 2. 目标与非目标

**目标**

- 工单创建 / 状态流转 / 新增处置意见 → 自动生成通知。
- 预警可**推送**（指定负责人或全体），生成通知。
- 提供未读角标与已读操作。

**非目标**

- 不做 WebSocket 实时推送（延续此前"不引入实时化"的决定），前端进入页面或轮询刷新。
- 不做邮件 / 短信 / 浏览器桌面通知。
- 不做消息免打扰、分组等复杂配置。

## 3. 设计

### 3.1 数据模型

通知落 `server/data/notifications.json`：

```
{
  id, type,                 // ticket_created | ticket_status | ticket_comment | alert_dispatch
  title, content,
  level,                    // 沿用预警四色，用于配色
  refType, refId,           // 关联对象（ticket / alert），前端可跳转
  actor,                    // 触发者
  userId,                   // 接收者；null = 全体广播
  readBy: [username],       // 已读人（广播消息按人记录）
  createdAt
}
```

**为什么用 `readBy` 数组而不是 `read` 布尔**：广播消息的已读状态因人而异，
一个布尔值会让"我读了"变成"所有人都已读"。

### 3.2 通知生成时机

| 事件 | 接收者 | 级别 |
|---|---|---|
| 工单创建 | `assignee`（空则发给创建者） | 取工单 level |
| 工单状态流转 | `assignee` + 创建者 | 取工单 level |
| 工单新增处置意见 | `assignee` + 创建者 | blue |
| 预警推送 | 指定 `assignee`，缺省全体（broadcast） | 取预警 level |

- 触发者是事件当事人自己时不生成通知（自己给自己发通知是噪音）。
- 通知生成失败**不得阻断业务主流程**：工单已经流转成功，不能因为通知写失败而回滚。
  因此钩子用 try/catch 包住并告警日志。

### 3.3 接口：`server/routes/notifications.js`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/notifications` | 当前用户可见通知（自己的 + 广播），倒序 |
| GET | `/api/notifications/unread-count` | 未读数（角标用，轻量接口） |
| PATCH | `/api/notifications/:id/read` | 单条已读 |
| POST | `/api/notifications/read-all` | 全部已读 |
| POST | `/api/alerts/dispatch` | 预警推送（放在 alerts 路由，语义归属更清晰） |

可见性判定：`userId === me || userId === null`；未读判定：`!readBy.includes(me)`。

### 3.4 与工单模块的衔接

在 `routes/tickets.js` 的创建 / 流转 / 评论处调用 `notify.push(...)`。
工单模块只负责"发生了什么"，通知模块负责"告诉谁"——职责分离。

## 4. 文件变更

| 文件 | 变更 |
|---|---|
| `server/services/notify.js` | **新建**：通知写入 + 可见/未读判定（纯逻辑可测） |
| `server/routes/notifications.js` | **新建**：列表 / 未读数 / 已读 |
| `server/routes/tickets.js` | 在三个业务动作后挂通知钩子 |
| `server/routes/alerts.js` | 新增 `POST /dispatch` 预警推送 |
| `server/index.js` | 挂载 `/api/notifications` |
| `server/data/notifications.json` | 运行时生成（已加入 `.gitignore`） |

## 5. 验收清单

- [ ] 建单后负责人收到通知；未指派时创建者收到通知。
- [ ] 状态流转、新增意见均产生通知。
- [ ] 自己触发的事件不给自己发通知。
- [ ] 广播消息（`userId=null`）对所有人可见，且已读状态互不干扰。
- [ ] 未读数随已读操作下降。
- [ ] 通知写入失败不影响工单主流程。
