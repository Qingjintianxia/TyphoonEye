# P2-5 单元测试与功能测试规范

## 1. 背景与问题

P2-1～P2-4 新增了大量**有正确性要求**的逻辑：规则引擎、状态机、并发写锁、跨用户已读语义。
这些逻辑的共同特点是：**手工点几下页面验证不出来**。

- 规则引擎的幂等性（ID 是否稳定）只有跑两遍比对才知道。
- 并发写锁"不丢数据"只有并发写 5 次才能证明。
- 状态机的非法流转只有穷举 `from × to` 才能确认没漏。

本系统此前**零测试**，任何重构都是在没有安全网的状态下进行。

## 2. 目标与非目标

**目标**

- 建立零依赖测试基线：使用 Node 内置 `node:test` + `node:assert`，**不引入 jest / vitest**。
  理由：项目是轻量演示系统，为一个测试框架增加数十个依赖不划算；`node:test` 已足够。
- 覆盖四类正确性：几何计算、规则引擎、状态机、持久层并发。
- 功能测试走**真实 HTTP 全链路**（注册 → 登录 → 预警 → 建单 → 流转 → 意见 → 消息），
  并**可与开发数据隔离**（临时 DATA_DIR），避免测试污染演示数据。

**非目标**

- 不做前端组件单测（成本高于收益，前端验证沿用 CDP + DOM 断言）。
- 不做覆盖率门禁。
- 不做性能压测。

## 3. 设计

### 3.1 数据目录可配置（前置改造）

功能测试若直连 3000 端口，会在 `server/data/` 里留下测试工单与消息，污染演示数据。
因此新增 `DATA_DIR` 环境变量，并收口路径拼接到单一模块：

| 文件 | 说明 |
|---|---|
| `server/lib/dataPath.js` | **新增**：`dataPath('tickets.json')` 唯一入口 |
| `server/config.js` | 新增 `dataDir`（默认 `server/data`） |
| `server/routes/auth.js` | `USERS_FILE = dataPath('users.json')` |
| `server/routes/tickets.js` | `TICKETS_FILE = dataPath('tickets.json')` |
| `server/services/notify.js` | `NOTIFICATIONS_FILE = dataPath('notifications.json')` |

> 这同时也是一次去重：原本 3 处各自 `path.join(__dirname, '..', 'data', ...)`。

### 3.2 目录结构与运行方式

```
tests/
  unit/
    geo.test.js            # 球面距离 / 最近点 / 风圈命中
    alertRules.test.js     # 规则引擎：幂等、降噪、升级、单城市单条
    ticketState.test.js    # 状态机：合法/非法/终态
    jsonStore.test.js      # 持久层：ENOENT 兜底、并发写不丢、坏数据降级
    cities.test.js         # 城市别名归一
  functional/
    api.test.js            # 真实 HTTP 全链路（独立端口 + 临时 DATA_DIR）
```

`package.json` 新增脚本：

```json
"test":      "node --test tests/unit",
"test:api":  "node --test tests/functional",
"test:all":  "npm run test && npm run test:api"
```

### 3.3 单元测试要点

**`geo.test.js`**

- `haversineKm` 用已知城市对做**区间断言**（不断言到小数点，避免不同公式的微小差异造成假红）。
- **非法输入必须返回 null**，且**不能返回 0 或 NaN** —— 距离算错比没距离更危险。
- `ringHit` 边界：距离**恰好等于**半径应算命中（`<=`）；`radius12` 优先于 `radius10`。

**`alertRules.test.js`**

- **幂等**：同一输入跑两次，ID 集合完全一致（这是工单/通知能稳定关联的前提）。
- **只处理 active**：historical 台风不产出预警。
- **同城单条**：`每个 (typhoonId, city) 只出现一次`。
- **降噪**：非声明城市的 `WATCH` 不产出预警。
- **极低压升级**：pressure ≤ 950 且距离 ≤ r7×1.5 时级别上调。

**`ticketState.test.js`**

- 穷举 `pending / processing / closed` × 3，与 `ALLOWED_TRANSITIONS` 逐项比对。
- `closed` 是全 False 的那一行（终态）。
- `canTransition(x, x)` 恒为 false（同状态无意义）。

**`jsonStore.test.js`**

- ENOENT / 空文件 / 非法 JSON → 返回 fallback，**不抛异常**。
- 并发 `mutate` 5 次各追加一条 → 最终 5 条（证明写锁有效，未互相覆盖）。
- mutator 抛错 → 文件保持原样。

### 3.4 功能测试要点

`tests/functional/api.test.js` 自行拉起服务：

1. `fs.mkdtempSync` 建临时目录作为 `DATA_DIR`；
2. `spawn('node', ['server/index.js'], { env: { ...process.env, PORT: 3101, DATA_DIR, JWT_SECRET, NODE_ENV: 'development' } })`；
3. 轮询 `/api/...` 直到服务就绪（**不能固定 sleep**）；
4. 全链路断言；
5. `after()` 关闭子进程并删除临时目录。

断言链路：

```
未知路径 → 404
注册 → 登录 → /auth/me → /auth/users
/alerts（含 breakdown 分项）→ /alerts/rules
/alerts/dispatch（广播）
POST /tickets（成功）→ 重复建单 400
PATCH pending→processing 200 → processing→closed 200
POST /tickets/:id/comments（闭环后仍成功）→ timeline 长度递增
PATCH closed→pending 400
GET /tickets/stats
GET /notifications → 未读数 → 单条已读 → 全部已读
跨用户已读隔离：A 全部已读后 B 的未读数不变
```

### 3.5 铁律

- 测试**不得依赖固定 sleep 等待服务就绪**，必须轮询。
- 断言区间而非精确值（经纬度、距离这类浮点计算）。
- 每个测试自己准备数据，不依赖执行顺序。

## 4. 验收标准

- `npm run test` 全部通过（≥ 25 个用例）。
- `npm run test:api` 全部通过，且运行后 `server/data/` **不产生测试残留**。
- `npm run build` 无新增警告。
